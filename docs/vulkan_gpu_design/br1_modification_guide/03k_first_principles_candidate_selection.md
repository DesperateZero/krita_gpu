## 0. 先固定优化对象与归因资格

**2026-10-11用户约束：先完整流程账，再选择设计。** 两个最近局部替代分别净回退和未取得收益资格，说明合法删量不能替代完整方案筛选。当前入口改为[92 §16.177](../92_br1_m6_m8_execution_baseline.md#pagestore-pipeline-refactor-core)，统一事实见[蓝图§19](../evidence/br1_pagestore_equivalent_pipeline_20261010/PIPELINE_PLAN.md#full-flow-ledger-audit)：先把原33项和所有当前方案放回同一流程，分别核验同义端点、同批CPU、对象数量、独占机制、锁/调度、资源峰值、入口覆盖，再比较完整设计。数据缺口不允许用“下一优先复用/读侧”跳过，也不原样续采扰动失败的细观察。范围和有限补数门须事前固定；无法区分最优则报告未知，不继续做容易命中的小机制。此为项目执行规则更新，安装技能及“排名/预测已验证”资格不晋升。

[§16.172实际反测](../evidence/br1_pagestore_equivalent_pipeline_20261010/README.md)补充：共同公共存储矩阵排除了绘画通用优化，确认重复Fresh周转；追加plan后才将cold计数关联到FreshPayload，不能直接把不同机制计数互换。read区间process CPU的大部分差额在其它线程，阶段边界不等于责任归属。即时读完成也不等于有retained reader；history起点不自动成为本操作旧值的恢复副本。本轮选中完整周转责任，尚无合法替代净价，不授产品蓝图实施或技能预测通过。

当前主目标是PageStore完整替代管线相对upstream同语义能力的效率。候选先归类为：**后端协议/表示本身的优化、必要业务接线、双方可共享的通用算法优化**。位置在merger/painter不自动违规，位置在pagestore也不自动取得基础性能收益；按责任和反事实对照判断。必要adapter、检查、失败回退与最终释放均计入替代成本。

通用候选不能仅因减少大量PageStore调用便升为基础性能主线。减少无效工作与完成同样工作更高效分账；要声称缩小后端差额，应在双方相同上层策略下比较，分别测通用优化在两边的收益。差额改善等于双方节省之差，缺upstream优化组不能假定其收益为零。此交互收益本身仍不证明PageStore内部算法改进。完整模型及下一准备矩阵见[证据口径](../evidence/br1_pagestore_comparison_scope_20261010/README.md)。

固定的是输入、真实读者可见性、历史保活、失败效果和完整生命周期，不是现有内部版本/复制/分配次数。新增能力成本单列合同与必要性，其落在普通共有路径上的费用不能从总账排除；禁用保证的快速实验不能领取为生产收益。本轮仅修正项目试行规则，安装技能和预测能力资格不晋升。

## 1. 需要补上的判断链

补数B的[36过程事件关联](../evidence/br1_pipeline_refactor_20261010/README.md#execution-work-correlation)补充：相同输入和Fresh数不足以证明总工作相同，还要把历史版本/root访问、退休尝试、job和前后台分工连到同一操作；即便这些计数稳定，也只证明已计机制。首次setup与后续manager须分开，双方都有的进程首次增费不能全归PageStore稳态。成功入队→出队的未覆盖时间不等于runnable，有限gate获取不等于所有锁等待，CPU端点不等于驻留/频率。观测模式的稳定计数不能替另一个off慢过程排除内部工作放大；原始慢态不删，未捕获不写成已解释。此次仍未取得目标合格机制价，技能排名/预测能力不晋升。

补数A的[68过程反测](../evidence/br1_pipeline_refactor_20261010/README.md#sampled-cost-capability)补充：内部时钟次数减少约75%，不等于机制价格已经可靠。必须同时检查完整process及前台扰动，不能只领取通过的前台格；off模式也有跨阶段/线程慢态，不能事后当外部噪声删除。下一需将实际执行条件与工作次数、重试/锁/调度关联，分清同工作变慢与多做工作；不靠换采样率、扩样或重排同类runner取得资格。原技能预测/排名能力不因此晋升。

```text
固定优化对象、要改善的业务端点、语义同义分母与成本差额
 → 对照业务必要图和当前执行图，审查工作拆分与调度边界
 → 从可观察合同推导必要事实、变化和寿命
 → 构造能实现的最小协议，找当前表示/频率/粒度的放大
 → 并列竞争解释，用最小实验区分
 → 对合法删除量、新增成本和全寿命副作用定价
 → 有据选入完整责任蓝图
 → 现有索引、迁移矩阵与统一实验
 → 对照事前预测、实际删除、净时间及剩余差额
```

必须分开五种结论：责任桶在哪里、哪里存在结构冗余、冗余能否合法删除、删除是否值得、最终实施是否兑现。源码存在冗余只到第二层；测试通过只证明相应合同；进入大成本函数不自动取得该函数的全部时间预算。

## 2. 从合同生成理想方案，不从容易改的代码生成

先为目标业务写一张**事实—消费者—变化—寿命表**：

| 要素 | 推导问题 | 产物 |
|---|---|---|
| 业务可观察结果 | 哪些像素、版本选择、失败结果和完成顺序必须相同？ | 同义输入/输出、起止与drain边界 |
| 必要信息 | 每次决策必须知道什么？谁实际读取？信息何时变化？ | 最小事实集，不能只列现有结构字段 |
| 保证来源 | 是外部合同、真实并发/晚读者要求，还是当前表示的便利？ | 保留保证及反例；可替换机制及证明义务 |
| 权限和失效 | 谁能修改事实？哪次解锁、epoch、预算变化会使它过期？ | 合法复用窗口、必须重验的边界 |
| 必要修改 | 本事件实际改变哪些字段、字节、归属？ | 最小delta；必要分配、索引和效果 |
| 最终消费者 | 何时可以释放，谁保证最后一次free与归费？ | 完整寿命与失败/取消/重试闭包 |

“当前代码检查了”不是必要性的证明；“本fixture没有并发”也不是删除公共保证的许可。能由原owner/锁/能力直接承载的事实，不先引入第二缓存或第二权限。替换保证的实现时保留其可观察合同；若确需改变合同，将其作为产品设计选择单列，不能领取为同义优化。

caller索引须记录**调用时已持有哪些锁、回调是否在被调用者锁内、是否允许再次进入原getter**。同为owner-locked入口不代表锁上下文相同。空历史任务首版虽然列出了rescan caller，仍遗漏visitPageKeys已持shard锁，导致真实容量恢复死锁；修订沿原持锁visitor保留旧准入，不能为统一快速路径解锁遍历或引入第二缓存。

据此构造可执行的理想算法，再与当前逐项相减。模型优先使用真实基数：唯一页P、必要版本V、读cut C、发生变化的事实D、实际消费者R、分片run G、重试F；解释每个倍增因子为何出现。分别判断：

- **必要新合同成本**：相对upstream确实多了任务，但尚需证明其最小实现；不能默认现有价格正常。
- **表示放大**：需要几个字段，却构造/索引/销毁整个状态；字节、内联容量、溢出和引用寿命分开。
- **频率放大**：事实没失效仍按dab/页/consumer反复求值；证明复用窗口，不能合并真实读cut。
- **粒度放大**：相同字节以大量小调用处理，或每元素进入协议；按实际batch大小分布比较，不能用全阶段总量冒充一个大batch。
- **工作转移**：提前准备、延后清理、增加驻留或改交worker；只有端点与最终free共同核验才判净删除。

严格下界、可构造实现的成本上界、工程目标、未验证假设分别标注。第一性分析通常给出“必须知道/改变多少”，不能凭它直接得出机器上多少ns。upstream合同不完全相同，其时间不是本实现的合法下界。

<a id="pipeline-boundaries"></a>
### 2.1 不把当前中上层拆分当作理想算法前提

[前台边界审查](../evidence/br1_pipeline_boundary_audit_20261010/README.md)确认：局部搜索无放大、两侧job数相同、已有range批处理，都不能证明operation/版本/交付的组合次数合理。先从真实消费者需要的中间状态、可见性和失败效果构造业务必要图，再与`job → merge → clear/composite → operation → 版本/发布 → 最终释放`对照。边界注明外部合同、真实依赖、当前实现选择或未知；公共单操作保证与上层是否必须拆成这些操作分开审查。

此前clear/composite融合已列出真实reader、失败与root寿命障碍，但“不能直接融合”不等于“该拆分已最优”。该边界已在§16.169有限范围落生产；descriptor节点和页内交接不默认续为主候选。局部优化须说明为何干预该层，以及是否增加上层替代的owner/状态/接口负担；已排除的小项和旧矩阵不重开。

[§16.170来源判别](../evidence/br1_post_fusion_boundary_audit_20261010/README.md)又发现：27个原本不重叠的输入区域，被原queue的包围矩形collect合并为19任务后，出现43008像素重访及704像素补洞。优化器降低job数量不等于降低实际工作；要同时关联输入集合、已派发区域和实际版本成本。投影96次冷准备中的24次同页不相交更新也不能当作同像素重算，必须区分页粒度复访与字节重访。按§16.171，同批精确区域合并降为独立通用候选、暂缓实施；几何16任务/78页访问不是净收益、生产资格或PageStore本体证据。原库与jobs均值还有约1.102ms跨模式差，支持责任前列判断，不支持精确成本占比。这次只更新试行经验，安装技能与“预测已验证”的资格不晋升。

总工作与调度关键路径分别证明。面积合并和整块accessRect排斥在源码存在，不证明该fixture有实际调度损失；反之沿用upstream也不证明适应新的页协议成本。需要ready/dispatch/run/finish及真实依赖关联，不能把wall−CPU当等待成本。

8次输入、4个显式callback、19个projection通知与内部版本数不能一概叫同义工作量：先核验每项真实消费者和合同。19是旧局部诊断匹配条件；新结构实验可把通知/任务/版本数量作为因变量，但须另冻协议并覆盖显示结果、顺序、延迟、取消和资源，不能仅凭最终像素一致减少应交付工作。旧冻结样本不回改。

<a id="pricing"></a>
## 3. 把结构差异变成有来源的净预算

对同一工作量x，建立候选i的条件模型：

```text
净CPU节省_i(x)
 = 可合法消除动作的原成本
 - 为实现替代新增的动作成本
 - 对其它阶段、重试、后台清理和驻留产生的净增成本
```

每项列出实际次数/大小分布、执行状态、时间来源及不确定性。必要动作即使保留，其单价也可能因布局/cache/并发变化，不能默认为常数。按独占作用域和对象寿命划分预算；构造与析构可分动作计数，同一析构不能由前台与后台优化各领取一次。

对新增过滤/准入查询，至少分开“拒绝空工作”“接受真实工作”“已有任务复用”“失败重扫”等实际路径。零过滤率路径只有新增检查而没有删除量，须在实施前定价或明确欠项，不能仅写“控制另测”便领取全局收益。任务合并/排程会改变请求总数：本次B跳过760次准入不等于净删760个节点，实际观察868→212才是656个差额；父任务数量也超出探索预测。稳定事实（非空任务212）与调度相关数量分开给预测范围。

先给**可支持的乐观上限**，用于排除对主目标无足轻重的项；再给具有依据的净收益范围，用于选择。父责任桶时间仅是宽松筛选参考，不是可删预算，也未必约束全局cache/调度连带效应；这些连带效应须另证。禁用保证、丢弃结果或跳过真实工作得到的加速只作敏感性提示，不自动构成合法实现或严格上界。

时间证据按用途区分：

| 证据 | 允许用途 | 不足以支持 |
|---|---|---|
| 精确计数、大小分布、汇编 | 判命中、数量、内联/实际调用与算法机制 | 时间占比、统计净收益 |
| 相同上下文的独占计时/硬件或栈采样 | 粗价、热点与候选上限筛选；注明观察扰动 | 精确因果归属；零样本=零成本 |
| 隔离微基准 | 解释大小、缓存、batch变化的条件价格 | 直接外推真实整笔收益 |
| 保持合同和真实工作量的局部替代/消融 | 估算可实现净收益；检查代码布局、调度等伴随变化 | 未覆盖合同的生产资格 |
| 冻结后独立、未插桩整包对照 | 确认已实现方案的端点净收益及原控制 | 自动分摊到包内各项、自动通过M6 |

单价缺失填“未知”，不能填零，也不能给伪造的置信百分比。价格区间是条件估算还是统计区间要写清；不把若干独立95%区间的端点机械相加为整包95%。CPU与wall分别预测；wall需解释关键路径、等待和并行，不能按CPU比例换算。

后继descriptor反测暴露计数实现问题：首版把emplace调用当成功节点，仅靠内部等式仍能自洽。关键数量须记录触发位置与操作结果，区分尝试、接受、实际对象及净差；作用域自检和重复运行一致不能替代这一步。修订观察保留旧样本，并从inserted结果确认320–324节点，不能将两个过程间4个节点差当优化收益。

计数证实某阶段不命中时，将它保留为解释归因的负控制：该阶段的表观收益不能领取给候选；其变化也不能作为固定偏差从目标端点扣除。读意图试行中Setup无候选删量却占全程表观节省的大部分，进一步说明完整寿命核验需要分阶段解释，不能仅报告一个全程正数。

## 4. 用能改变决策的实验选择候选

先列竞争解释，再选择最小判别。例如相同metadata热点可由“临时事实构造”“原索引/provider/proof”“真实必要读cut与工作量”解释。每个解释写出成立时与不成立时应看到的数量和时间变化，实验应能分开它们；否则只是再次看到热点。

先核对旧候选是否已被当前快路径覆盖，并按每个实际输入记录迭代。descriptor索引最大112项，但208次hint全命中，其余110–114次搜索均首项命中；Undo单次helper的56次比较来自56个输入。容器大小、helper调用数、batch大小和每输入的遍历长度不能互相代替。以低成本判别选中一个候选，也不意味着它已在净收益榜前列。

先用已有有效数据。缺频率就补计数；缺净价就做有界合法替代；怀疑规模放大就选择能区分公式的实际分布。不得把已完成的108过程责任覆盖账再跑一遍。探索性原型可在没有收益定价时实施，但必须标为**判别实验**，有范围、成本与停止条件，不能凭可运行就升级为整包产品改造。

实施前确定目标端点、最小值得收益δ和可分辨精度。δ由当前业务目标、可回收差额、改动复杂度与维护成本解释，不设通用毫秒/百分比门，不恢复旧30%门。若实验只能分辨远大于δ的变化，就不能用区间跨零宣称候选无效；选择可行的新判别方式或保留未知，不追加样本直到显著。

| 选择状态 | 依据 | 后续动作 |
|---|---|---|
| 待判别 | 有合法结构候选，频率/净价/替代可行性仍缺关键证据 | 仅领取有界诊断或原型 |
| 不进入本次主优化 | 可支持的收益上限不足以影响本目标，或实际未命中 | 记录适用条件；不是宣判永远无效 |
| 合同不成立 | 替代删除了必要输入、保证或真实工作 | 修改方案；不得用跑分快作证 |
| 可进入蓝图 | 合同可构造、命中明确、条件净预算有据且值得、主要副作用有验证方案 | 深化完整责任并建立索引/矩阵 |
| 实测未决/否决 | 整包区间无法裁定/发现真实回退或不满足事前标准 | 保留样本和原因，不改写旧预测 |
| 实测兑现 | 删除量、主要端点净收益、控制和实际终点满足事前标准 | 按原阶段门另判资格 |

按**有依据的可回收毫秒、影响业务端点、证据强弱、完整迁移风险**排序；不要用任意加权分数制造精度。没有足够收益证据时，可按“哪一个低成本实验最能改变排序”推进。全是未知时不能宣布剩余差额都必要，也不能把任何看起来优雅的重写列成最高优先级。

明确区分三张榜：**当前责任CPU成本、相对基线的额外成本、合法替代的净可回收成本**。调用/分配/free次数榜不是其中任一时间榜。候选通过某个小改动的δ门，只说明可能值得做，不证明它处于主目标的榜首/前列；声称前列需给同分母的竞争责任及净预算依据。未取得额外/可删分摊时，只写“较大的调查责任”，不能将其整个桶价变成优化项。

已有探索与确认数据也要用于校准精度。空任务δ0.1ms，而最终95%区间宽1.432ms；探索通过仍不足以支撑稳定识别小收益。下一项在实验前列明已有噪声尺度、目标效应与可行精度，不能事后不断加样，也不能降低δ制造成功。若只有宽工程范围，预先说明它用于粗筛而非精确预报，不因点估计落范围内宣称模型准确。

## 5. 进入蓝图的最小记录与原流程衔接

复用项目现有账本，一项只保存一份以下信息，不新增第二实施状态账：

| 字段 | 必填内容 |
|---|---|
| 目标与身份 | 业务端点、源码/库、同义输入、实际父版本、upstream用途；候选在当前成本/额外成本/可删净价哪张榜有依据，未知项明确标注 |
| 理想与当前 | 必要事实/消费者/失效窗口，当前放大公式，合法替代算法 |
| 删除许可 | 删除/保留合同，失败、重试、晚读者和最终释放反例 |
| 实际命中 | 分支频率、大小/batch分布、原成本来源及覆盖范围 |
| 预测 | 删除量、新增量、净ms条件范围、目标δ、已有噪声/可行精度、主要不确定性；范围预测与探索点参考分开 |
| 竞争解释 | 什么观测会推翻它；最小判别方法和停止条件 |
| 关联预算 | 与其它项共享/互斥的对象和寿命；合并收益如何避免重复 |
| 选择与交付 | 待判别/选入/排除及理由，索引/矩阵链接，独立验收方法 |

同一owner、表示和寿命的多项优化可以一起构成最小完整责任，不退回“发现一点改一点”。但包中须区分**主要收益项、实现依赖项、顺带低成本清理、必要保留项**。依赖项不虚领收益；独立且未知价值的重构不因“避免遗漏”被捆入主包。只对尚有决策价值的相互作用做消融，不要求每个hunk各跑一套完整矩阵。

算法设计调整若减少了原定删除量，应在实施前更新预算并重判优先级。例如“直接消费原事实”变成“构造薄状态后复用原策略”，安全与复用可能更好，但不能沿用完全删除临时状态的预测。旧目标与旧预测保留，不能通过改验收文字让较弱实现看起来完全达成最初价值目标。

## 6. 收口与技能升级的验证条件

每次用同一表比较：事前合法删除量/净时间范围 → 实际删量 → 实际新增成本 → 未插桩CPU/wall区间 → 未解释残差。解释预测偏差属于模型、命中、实施偏离、副作用、测量精度还是控制回退；区间跨零不判零收益，宽预测范围也不算准确预测。

空历史试行独立点估计0.4545ms落在0.2–1.0ms工程范围内，但95%区间[−0.028,1.404]不能确认正收益；不得据“点估计预测对了”宣称技能预测能力已验证。探索通过只允许进入验证，生产确认仍可拒绝候选；保留安全反例、修订、控制和回退，不追加样本追逐一次正向闭环。此类结果证明否决流程实际生效，不能计作正向成功率。

“流程有效”至少要在一个**事前冻结的新候选**中演示：

1. 从合同推导候选并排除一个有证据不适合主目标的竞争选项；保留被选和未选理由，不能事后只展示赢家。
2. 实施前给出足以影响选择的删除量和净收益范围、成立条件、δ及判别/停止规则；探索样本不进入独立确认样本。
3. 按原蓝图—索引—矩阵完成责任闭包；预测变化有事前记录。
4. 固定实验确认主要机制与有价值的净收益，原控制/资源/终点另判；若失败，准确否决也是流程的有效行为证据，但不能单凭失败就证明正向预测能力。
5. 对未兑现部分做可核查解释；不以增加样本、换端点、缩小原目标取得“闭环”。若尚缺正向验证，保留试行而不无限追逐一个正结果。

已有案例回放只检查规则能否识别已知反例；它受事后信息影响，不给命中率或成功概率。已经暴露的缺口可先作有限纠错更新，正文只保留通用判断，详细候选模板/案例按需放references；完成上述前瞻闭环后，再评价选择与预测能力是否获得正向支持。运行skill校验只能证明结构，不能代替行为效果。BR1的具体次数、δ、样本数不固化为通用技能规则。
