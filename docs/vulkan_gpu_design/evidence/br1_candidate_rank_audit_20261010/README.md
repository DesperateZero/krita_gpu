**上轮命中了高频、可删除的空任务，但没有证明命中性能榜首或前列的可优化时间。** 本轮新测量更支持将history空任务降为次级候选，不能因为有522/656个节点可删，就继续优先细化其getter或事实传递。前台逐代际准备/发布仍是当前已观测的最大管理责任；其合法可删预算仍须另证。

产品保持c13c442493（生产源码与d182a34bd0相同，仅已有测试13行）；原库ba5876d6。没有产品/测试修改，没有新增候选性能样本。旧64过程确认及全部否决保持，只分析旧结果并按[新协议](PROTOCOL.md)运行20个有限责任观测过程。全部60 QTest、19updates/像素/UndoRedo/销毁、加载库/依赖及退出通过，M6资格与技能升级状态不变。

## 2. 为什么上轮的“排名”依据不够

原释放普查中21/185条Stroke样本指向Work erase，回答的是“哪些对象经常释放”。它没有回答每种对象的CPU价格、前台/后台等待、可删比例，也没有包括malloc之外的全部工作。一个短命map节点出现很多次，可以仍然比一次复杂root/业务准备便宜。

上轮0.1ms参考线回答“小型、无新owner的改动是否可能值得做”，并未回答“它是否足以优先承担upstream主要差额”。把探索门通过当作前列瓶颈确认，是选择层缺口。独立确认及时否决了产品候选，但没有补齐选择层排名。

原同期upstream冻结差额7.643ms只保留为其自身批次的结论。本轮没有新upstream过程，不计算0.4545/7.643的追回比例，不将本轮责任价格除以旧差额。**当前责任成本榜、相对upstream差额榜、合法净收益榜是三张不同的榜。** 本轮得到第一张榜的有限版本，后两张仍有缺口。

## 4. 观察扰动与跨阶段限制

raw/off/coarse/history的Stroke CPU中位为16.1095/15.8120/16.5550/16.7675ms。history相对coarse增加0.2125ms，投影CPU比1.01377，未触发事前>0.25ms或>1.15的降级线；但已经接近0.25ms，且这不是无扰动证明。coarse比off高0.743ms，off也比raw更快，说明布局、调度及观察费用存在，不能扣一个固定时钟价。

原分析器拒绝跨阶段事件，新增后台范围暴露了边界：每个history过程有约0.0184–0.0208ms job CPU跨出Stroke。保留首版分析器及[修订说明](ANALYSIS-REVISION.md)，对全部已记录事件先核验CPU/wall父子、线程与observer errors/overflow/active=0；闭合self与跨阶段self分开，不删样、不重采。

history job含其pass，二者不能相加。0.6369ms是已记录阶段内范围的值；stage0开始并延伸进Stroke的scope未记录，前台request/队列/调度也不全在其中。因此这里既不是history全寿命的精确总量，也不能构成空任务候选严格上界。后台尾小于前台管理链与history的粗价差，并不消除上述未覆盖限制。

## 5. 排序和技能裁决

1. **空history Work降级为次级候选。** 原优化已回退；不默认继续做“传递history事实”微调，也不扩样追求显著。只有新的证据证明前台准入/跨层重复有足够预算，才重新领取一个独立责任。
2. **主要调查方向回到前台逐代际准备/发布**，其次是尚未拆清的operation/read-merge。它们是已观测大责任，不是已找到的头部可删除项。必须对稳定事实在base/provider/ledger/metadata/binding交接中的生产、消费和失效做比较，再给原独占成本、合法删量、新增成本及净ms。
3. **技能仍试行。** 已有否决能力和数量实施能力；排名准入与精度校准仍不足。下一候选卡必须在事前同时给：当前成本榜位置及分母、可删除份额依据、净收益排序区间、目标δ与已有噪声/精度。单纯“有大次数+一个正探索点”不得命名为榜首或前列。

本包到此停止，生产源码、安装skill、M6/M7/M8 0/3及2/20校准不变。没有以更多细时钟或新优化去延长本候选。

最终核验：全部构建输入和20过程实际加载依赖hash一致，产品tracked干净。观察器mode0/2/3自检通过，覆盖stage0不计数、scope前线程bank初始化、另一线程纯计数、父子CPU账、异常展开及重复finish；原metadata数量观察确实关闭。自检不是额外业务性能样本。
