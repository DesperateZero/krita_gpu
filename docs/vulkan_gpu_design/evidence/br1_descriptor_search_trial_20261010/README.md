## 1. 为什么选择这个判别

[前台事实/消费者/失效窗口与代码索引](PIPELINE_AUDIT.md)比较base、物理接纳、binding、descriptor、completion、proof和operation。已合并的锁外准备不能重领；reader物化默认源、驻留移动、独立proof撤销等均有真实变化或消费者，不能仅按相同key删除校验。尤其同一版本可有两个独立proof，原测试要求撤销其中一个后另一个仍有效，不能用一个sealed bool替代整套proof责任。

R08是旧指南仍开放、且存在显式线性后备搜索的候选，适合用低成本计数区分“实际复杂度放大”与“正常路径已被base hint覆盖”。这是**判别的选择理由，不是可回收时间排名**。没有把旧前台4.043ms桶价授给它。

[协议](PROTOCOL.md)先冻结四个raw/count/count/raw过程，不做逐比较时钟。审查发现首版节点计数实为emplace调用次数后，按[修订记录](CORRECTION.md)只补两个count过程，保留首版源码、库、数据和分析器。全部6个matched过程、18 QTest通过，像素、19updates、8segments/4callbacks、Undo/Redo、销毁、加载库及依赖、退出/reap均核对。

## 2. 实际算法量，而非容器上限

以下使用**修订后的两个过程**；范围是样本全范围，不是置信区间。全Stroke，不能直接替代投影子集的132分母。

| 量 | Stroke | Undo | Redo |
|---|---:|---:|---:|
| helper调用 | 333–334 | 2 | 58 |
| 输入版本数 | 320–324 | 56 | 56 |
| base hint存在／相等 | 208／208 | 0／0 | 56／56 |
| 全索引比较／命中 | 110–114／110–114 | 56／56 | 0／0 |
| 候选节点表比较 | 0 | 0 | 0 |
| 新descriptor对象分配 | 2 | 0 | 0 |
| emplace尝试／成功节点 | 320–324／320–324 | 56／56 | 56／56 |
| 当时原索引最大项数 | 112 | 112 | 112 |

每个命中至少比较一次；所有调用的比较数都等于命中数。因此，**超出首项所需比较的遍历次数为0**。Undo一次helper最多56次比较并非扫描长度56，而是批量输入分别各比较一次。零输入helper也保留在调用数中，不混成有效版本数量。

理论模型从“可能按全部descriptor数量D扫描”收紧为本用例的`208次直接hint比较 + 110–114次首项比较 + 2次新值分配`，另有320–324个版本索引节点。若替代目标只是消除搜索中的额外遍历，这批可删数量为0；改成hash/cache还需相等判定与维护，当前没有收益依据。

0.5ms参考量若全由110–114次比较回收，需每次承担约4.39–4.55μs；这只是反算条件，**不是测得单价或可删除时间**。本次所有比较都在首项成功，已经足以否定“遍历许多已有descriptor”这一具体解释，故没有追加隔离扫描微测，也没有启动产品候选/收益确认矩阵。

320与324的差异发生在相同修订观察实现的两个过程，外部同义检查通过；不能领取为优化删量或强行固定为324。首版两个过程各324仅证明当时的调用数，最终成功节点证据来自修订后的返回值检查。2个新对象也不自动等于两种全局唯一布局，更不等于仅需要两个版本身份。

## 3. 剩余问题没有被这次结果解决

当前表示将少量共享descriptor对象挂在数百个按版本的索引节点上。**这提出了版本映射全寿命的候选问题，没有证明数百节点都冗余。** 真实读写、default restore、seal/commit、晚读者与按版本回收仍需找到正确布局。若拟把布局引用并入原metadata版本记录，必须覆盖字段/arena容量增加、原接受窗口、指针寿命、拒绝和最终收费；不能只删除m_descriptors表，或把节点数乘一个free单价作为净预算。

本轮没有测节点建立/安装/查找/最终释放的整体价格，也没有新upstream配对，不能填回旧7.643ms差额；更不能从排除搜索推断所有管理成本不可避免。下一仍并列比较前台事实交接、版本索引全寿命与operation/read-merge，先按哪个有限实验最能改变净收益排序选取；**不默认将descriptor节点升为下一榜首**。

## 4. 对技能的反测

| 判断环节 | 实际结果 | 欠缺或执行问题 |
|---|---|---|
| 先看命中再授预算 | 已防止将112项索引乘320余输入误估成大量扫描，再实施一个缓存 | 旧开放候选必须核对后继快路径；helper次数、批量输入与每输入迭代不是同一基数 |
| 必要事实推导 | 区分布局值、版本映射、独立proof身份与物理驻留 | 正文仍偏抽象；跨层事实表须显式写“谁改变、谁使其失效、哪个消费者决定基数”，才能构造完整替代 |
| 数量核验 | 首版把emplace尝试命名为新节点，人工复核后修订 | 技能已有“尝试不等于净删量”，本次仍未在探针实现中落实。不是简单再加一句提醒；关键计数要从实际返回/身份核对，不能只验自洽等式 |
| 验收与价值选择 | 当前候选被有限结束，未开启无预算产品改造 | 拒绝弱候选的能力有新实例，**生成高价值候选的能力仍未证明**；不能把累计排除次数当技能成功率 |

本轮不以这些反例再次扩充通用技能正文。先在项目03k记录可执行检查与尚缺能力，后续有新前瞻证据再决定是否需要提炼。数量实施、结构校验和语义测试均不替代性能价值验证。
