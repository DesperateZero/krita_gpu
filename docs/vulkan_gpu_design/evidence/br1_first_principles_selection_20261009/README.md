本轮交付[03k候选选择流程](../../br1_modification_guide/03k_first_principles_candidate_selection.md)。修正发生在蓝图之前：从必要合同推导可构造算法，对实际命中与可删除净时间定价，再选择完整责任进入原索引/追踪流程。不是再增加一个实现清单，也不把结构审查通过当作性能价值验证。

初始回放批次产品保持`d182a34bd0196079bc40d2ab7d00b8e326e4a58a`，文档起点`875beadf2`。该批产品/产品测试改动0，新性能过程0；当时安装的`algorithm-cost-optimization`保持原版，起点SHA256见[复算结果](replay-result.json)，冻结裁决见[92 §16.160](../../92_br1_m6_m8_execution_baseline.md#first-principles-selection-trial)。本篇§5继续追踪后续验证，最新[技能纠错更新](../br1_optimization_skill_correction_20261010/README.md)不改写原批次结果。

## 1. 原流程缺口与这次修正

原技能和03h已经要求“数量不等于时间”“未知单价不承诺ms”，所以失败原因不是完全没有这些概念。缺口是：**没有时间承诺的结构优化，仍能被标成待实施并组成较大的产品改造包。** 责任桶有权重替代了具体动作有权重；不报虚假预测解决了表述问题，没有解决选项排序问题。

新流程把理想模型拆成两件事：先定义在合同下必须知道、改变、保活的最小事实，再证明具体表示/频率/粒度差异在当前workload中有值得回收的价格。未知项先进入有界判别实验；“可进入蓝图”须有合法算法、命中证据、条件净预算及控制方案。保留原完整责任迁移能力，依赖项和顺带清理不虚领独立收益。

实施方式改变后也必须重算预测。03h采用紧凑WorkingVersion而非完全消除临时状态，具有复用唯一政策的理由；它不能沿用后者的删除预算。此轮原协议本就没有ms承诺，因此不能伪造一个预测误差百分比；只能判定**主端点选项价值证据偏弱，数量落实与索引闭环有效**。

## 3. 数值复算与结论边界

[replay.py](replay.py)从已冻结JSON的块统计量重建原bootstrap，检查9个端点的点估计/区间与原摘要一致，提取14类实际计数分布并绑定输入hash。没有替换样本、增加性能过程、改变原估计量或得到独立样本。

```sh
python3 docs/vulkan_gpu_design/evidence/br1_first_principles_selection_20261009/replay.py
```

相对直接父版本，Stroke CPU降3.88%[−0.28%,8.82%]，无法确认稳定正收益；Undo/Redo/Teardown CPU分别降11.45%/7.33%/9.08%，各自pointwise区间为正。相对upstream仍多7.643ms（配对差中位）。这些原结果支持主目标命中偏弱，但没有逐项消融，不能判定每个子项都无效或精确量化费用抵消。

含Setup的五阶段CPU仅降0.20%不作为主优化价值判据：Setup约占400ms量级全程中的大部分。主要诊断仍看预先指定Stroke端点及绘画/清理阶段绝对时间；Setup和全生命周期继续作为必要控制。不能事后换端点使本包通过。

“9个端点复算一致”是算术与证据一致性，**不是9个流程有效性测试**；14种计数不形成14个独立性能实验。没有可报告的流程命中率或概率置信度。
