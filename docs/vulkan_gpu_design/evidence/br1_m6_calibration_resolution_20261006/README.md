## 已确认与未确认

**原镜像自身也有跨进程变异**：D2原QoS A/A仅2/8描述性等价，最大单次操作8.903ms。异镜像原QoS也仅2/8。此为各桶未经family调整的95%诊断区间，不是正式校准通过数；不能把A/A噪声解释为控制镜像的确定回退。

**“优先级太低”不符合直接观察**：预检及正式诊断的主线程原请求QoS33（user-interactive），显式user-initiated改成25。它降低了请求等级，不能描述成提升优先级。记录的是请求/有效QoS类别，不能据此证明具体core、频率或获得的调度服务；nice均0。整窗口rusage包含warmup、setup、验证和退出，不作operation内精确抢占归因。

**随机哈希布局是真实工作变量，但不是已确认主因**：原metadata/admission/publication索引捕获`QHashSeed::globalSeed()`；稳定PageKey分shard hash未变。D3仅在证据进程启动时设置`QT_HASH_SEED=0`并读取实际globalSeed，未修改产品默认。hit的paired log吞吐标准差有所降低；native-pin的A/A与异镜像变化方向不一致，零seed下ARM native-pin更宽。不能选择其中一个有利桶当作完整修复。

**尾不能免费删除**：D1慢操作仍可能包含合法产品工作；目前无法严格分摊为OS抢占、锁等待或CPU执行。完整吞吐仍用completed work/operation wall，median只辅助定位。延长窗口只提高同义操作的累计测量时间；单个20ms事件的窗口占比从31.25%变成3.90625%是条件算术，不保证事件数量固定、噪声独立或实际分辨率满足2%。

## 理论与实际：本轮改善的是计量分辨率

|---|---|---|
| 单次操作工作、prepare/seal/commit端点及完整退出保持；只将累计操作时间提高8倍 | 完整`sample()`函数体SHA与上一包相同，全部原始操作有效；D4取得8836604次操作 | 工作模型兑现；setup/验证/close/drain仍另计，没有隐藏慢样本 |

## 身份、失败与重现

原候选、normal-on选择镜像及2504个源码/运行时输入沿上一包身份复用；每轮开始/完成都核对，选择镜像必须实际加载。D2、D3、D4不与构建、另一性能实验或分析器并行。x86_64为本机Rosetta，不外推原生Intel。每进程全部operation ns、像素与有效工作检查、命令、环境干预、实际退出/timeout/reap、预算和完整退出保留。

初版QoS查询误用了SDK API参数数目，两个架构编译失败，尚未产生计时样本。保留[初版源](baseline-initial-api.cpp)、各初版commands、[问题记录](execution-issues.json)与可用截断日志；随后按本机SDK三参数签名修复，再构建两个最终探针。新seed探针两个架构构建及24个预检通过。失败不替换已取得的性能样本。

分析脚本按各自协议单独读取全部固定过程：`analyze_diagnostic.py`、`analyze_seed_diagnostic.py`、`analyze_window_diagnostic.py`。不得把三轮混成一组，不得把内循环当独立过程，不扣镜像偏差、不删尾、不按结果扩样。

1920个诊断过程包含10982226个有效操作样本；72个预检另列，内循环不是独立统计单位。生产/测试改动均0、公共API/持久字段/owner增加0；变化仅为证据夹具、协议、分析及活动文档。当前11180/0/0安全、6资源探针和结构/工具资格继承同一已核验输入，未重跑完整安全矩阵。预算close快照在Store仍存活时取得，metadata仍可能live；实际Store销毁和drain在sample返回前完成，不编造销毁后快照。

[原始归档](raw-evidence.tar.xz)保存所有新过程、失败构建材料、冻结协议/脚本/探针及实际加载的两个镜像字节；[成员与SHA](artifact-manifest.json)逐项核验。依赖身份由start-identity绑定，旧1600个过程引用[上一包原始归档](../br1_m6_provider_borrow_20261006/raw-evidence.tar.xz)，未复制改写旧裁决。重现须准备这些冻结输入，按各协议在**新的独立输出目录**运行；当前runner刻意拒绝覆盖原样本。
