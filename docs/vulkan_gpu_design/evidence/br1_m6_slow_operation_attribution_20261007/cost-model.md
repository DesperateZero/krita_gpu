# 此次诊断如何改变优化选择

令一次同义操作为`T=C(state, layout, cache, execution environment)+W`。C是实际CPU执行时间，W包括未运行和等待；CPU时钟只分离计时覆盖，不给出每个产品责任的可删除量。ARM的thread CPU经busy/sleep校验可用；Rosetta的thread CPU覆盖仅约2.4%，不能拿`wall−thread CPU`宣称97.6%等待。Rosetta process CPU可覆盖busy，但包含其他线程。

旧D4全向量精确分解：`log(rate_R/rate_L)=log(median_L/median_R)+log((mean_L/median_L)/(mean_R/median_R))`。形状因子包括普通波动与长尾，两个分量有协方差；不能把方差份额当CPU因果比例，不能用median或去尾数据替换吞吐门。≥1ms操作在合并同架构/K/case的512ms数据中占操作总时间约0.034%–0.217%，按单cell最高约0.278%；少见尾不足以独自解释全部残差。D1有限161087操作未见≥1ms，不等于产品尾已修复，也不能追加到出现尾。

D2固定算术reference在产品变慢时也有变化，但全量Pearson≥0.6且至少10个≥2median事件仅4/16过程；按事前判据，不宣布完整同步解释成立。D3移除CPU/rusage/reference，只在原wall端点外查询CPU编号，30个有两组同编号样本的过程全部观察到0–5组产品中位比6–9组慢3.11–5.33倍。两过程没有0–5组；K16部分慢组仅1–2操作，证据较弱。SDK明确查询结果瞬时有效，不能断言区间全程在同核；IORegistry没有返回核类型字段，后继有效当前K16 Time Profiler标签实际补出0–5 E/6–9 P。仍缺频率/外部负载/缓存的精确因果轨迹，不把映射本身当全变异分摊。

这不是把某个3倍热点全当作可删算法成本：同一timed代码、页数、copy/handoff、输出与退出保持，执行条件会改变必要工作单价。没有合法可删产品时间预算时，不通过增加claim缓存/改容器/改产品QoS追逐此差异。此前按重复次数做的小改动影响小，不证明剩余所有算法均理想，也不证明管理成本没有优化空间；它说明尚未给候选建立足以覆盖测量变异的绝对时间预算。

用于说明精度敏感度的条件模型（不是实测归因）：若两执行环境的代表性时间比r=3–5、慢环境占比为p，则忽略迁移及其他状态时`mean=t_fast×[1+p(r−1)]`。左右p只差约0.5–1个百分点就能带来约2%的比值偏差。真实数据还含迁移、缓存、hash和等待，不用本式校正样本或计算门禁。固定工作变慢也不是已证明完全由核类型/频率造成。

原编排将两个相反顺序pair分散到其他组两边；就地ABBA使二者更接近。理想共同线性漂移可抵消，随机核选择、cache冷效应、process特有layout仍保留。I1/V1同时跑global/local、固定192过程，实际间隔从15–27s降到0.004–0.012s；但两策略均0/4满足±2%，local 3/4增大SD，候选否决、不推广、不续采。不能把旧正式64ms结果借新诊断追认，也不按诊断失败降低正式阈值。

本包没有新的产品加速百分比、CPU理论最小μs或全局因果置信度。可重复现象与统计资格分开：C1计量覆盖、D3观察重复和V1描述性区间各自回答不同问题；M6正式校准、匹配hit/miss、metadata驻留和CP0 required继续独立裁决。
