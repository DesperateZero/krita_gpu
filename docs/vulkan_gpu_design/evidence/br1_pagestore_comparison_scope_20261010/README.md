## 2. 按责任划分，不按文件夹划分

| 对象 | 包含的成本与必要合同 | 证据用途 |
|---|---|---|
| PageStore 同语义替代管线（主线） | PageStore、必要 adapter/manager 转接、读写准备、版本/COW、发布、history、预算与最终回收；对应 upstream 原 tile/data manager/memento 的能力 | 相同上层操作与可观察合同下的基础差额、合法可回收成本及优化前后变化 |
| 必要业务接线 | 原 merger/painter 等知道消费者与可见性边界，向后端表达所需操作；额外资格检查、失败回退与负路径成本 | 单列机制与净收益，并计入实际替代成本；不是把全部上层改动排除出责任 |
| 通用算法优化（独立候选） | 区域合并、减少无效合成、两边都可采用的 clear/composite 融合思想、通用 kernel/调度改进 | 业务收益单列；要声称 PageStore 相对收益，需双方匹配策略的对照 |

上层少发请求可能缓解昂贵协议，但不能回答“为何同样请求更贵”。反之，不能固定现有内部 generation、copy、allocation 或 seal 数量，阻止 PageStore 在相同外部合同下改进自己的协议。一次融合同时含有通用思想与后端专用实现时，必须拆开两种结论。

新增能力的费用须注明具体合同、实际消费者和最小必要工作，单列功能溢价；不能一概称为正常管理费，也不能为凑同义对照关闭生产保证后领取收益。若 upstream 无对应能力，该行不得冒称直接同义比较；启用该能力给普通共有路径带来的费用仍计入分支总成本。

## 3. 对称比较与完整生命周期

令 S0 是双方共有的原业务策略，S1 是双方都实现的同一通用优化；P/U 分别是 PageStore 替代管线与 upstream：

```text
同策略基础差额：D0 = P(S0) - U(S0)，D1 = P(S1) - U(S1)
通用优化各自收益：gP = P(S0) - P(S1)，gU = U(S0) - U(S1)
相对差额改善：D0 - D1 = gP - gU
```

以上是同一统计量/匹配实验上的成本模型，不能直接加减不同样本的中位数或置信区间。仅有 gP 就只能报告分支收益；缺 U(S1) 时 gU 未知。即使差额改善成立，也先说明工作量与后端成本的交互，不能冒称 PageStore 内部算法已改进。基础比较至少需要一对相同策略；无须为取得 S0 对照先做完整 upstream 优化。

恢复 clear/composite 拆分只消除一个已知不对称，不自动建立 S0。必须清点该调用闭包内其余通用算法、kernel、调度及配置差异，逐项匹配或保留独立控制；未闭合的差异仍算混合整链差额，不能改标签冒充基础归因。

同义合同冻结逻辑输入、内容/区域、操作与真实读取顺序、current/exact/history 的可见结果及保活寿命、失败/取消、finish、Undo/Redo 和最终 free/drain。固定依赖、构建/加载库、线程与资源条件；不以终局像素相同代替中间读者合同。真实 canvas 会同步读取投影，headless callback 计数不能代替显示可见性证明。

两层证据必须连接：一层是上述存储替代链的同义操作对照，另一层是实际 stroke 的完整 CPU、wall/延迟与资源结果。前台省时但后台或 teardown 增时不算净删除；纯 memcpy 或仅热缓存微基准不能代表含 COW/history 的基础能力。内部动作数量作为解释结果记录，不强制两套算法相同。
