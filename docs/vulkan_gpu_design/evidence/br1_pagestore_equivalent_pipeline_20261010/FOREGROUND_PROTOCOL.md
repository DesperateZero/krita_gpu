# 前台/后台分界追加判别（前瞻冻结）

原79进程完成后，共同矩阵K16/16次覆写的read区间额外process CPU约4.95ms，但此时写入产生的后台清理可能并发执行；不能把区间CPU直接叫读管线本身的价格。

追加且仅追加4个共同存储进程：current/upstream/upstream/current，原8行输入和4次manager寿命全部不变。两侧同一夹具增加CLOCK_THREAD_CPUTIME_ID，与process CPU/wall在相同边界累计；仍使用原未插桩image库。ARM64时钟范围沿已有校准，只作描述性分界，不补原8块样本、不授新的95%区间或净收益。

保存派生夹具diff、实际编译/库/输入哈希、退出和语义结果。原样本及分析不改变；任何失败停止。对齐比较写、读、全case的前台与其余process CPU，确认下一责任应在读本身还是前次写的后台尾，禁止按差值直接认定具体worker归属。
