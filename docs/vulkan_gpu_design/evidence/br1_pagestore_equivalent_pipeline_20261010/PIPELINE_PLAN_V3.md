## 3. 从本次结果提取的全管线形态

**下一方案的中心是让语义事件只生成所需工作，让已知事实以最小表示到达真实消费者。** 原型已改善寿命与归属；剩余工作要审查保留服务的触发规模和执行内容，不能用“owner 已统一”代替效率证明。

```mermaid
flowchart LR
    A[公开操作与真实可见点] --> B[一次范围准入与选择]
    B --> C[真实目标及费用准备]
    C --> P[私有内容执行]
    P --> D[原结果行与全 D 接受]
    D --> E[原事实统一接受政策]
```

图中“原行”不意味着把所有 owner 合并，也不意味着一次锁覆盖整链。每项权威保留原锁域；跨真实失效边界才复验相关事实，callback 在合法解锁窗口运行。没有真实可见点/独立失败要求的内部拆分可以融合；固定测量中的 68 seal、1088 行是观测量，不是算法定理。改变它们须从公共合同重新证明，不能只比最终像素。

|---|---|---|---|

目标管理模型是按**真实事件**而非现有函数计费：

`I管理 = N操作·u准入 + N选择·u选择 + N变化行·u私有/接受 + N新物理·u建立 + N真实费用组·u结算 + Nroot变化·u发布 + N独立holder·u保活 + N退休尝试·u推进 + N存储寿命·u完整存储 + I其余`。

这些项须先定义互斥边界；包含存储服务的父责任要扣除同一子价，不得重复相加。失败、重试、空命中及晚消费者单列实际路径，不能用一个平均 `u` 覆盖不同动作。稳定容量消除了重分配，不自动消除每代值构造、字段重置、引用和查找。本轮补得若干源责任估价及上层协议净价，各 `u` 的全场景合格价格仍未齐全，此式不是已证明的最低成本。还须将上层事件生成的后续义务单列：`N后续 = g(实际发布/保留、保护关系、接受/拒绝、调度政策)`；不能假设各层 N 相互独立。

净替代价按 `Σ[(N旧−N新)u旧 + N新(u旧−u新)] + 其它旧−其它新` 估计，同时计回更早准备、保活、峰值、重备、失败和最后退出。物理容量共享、CPU 指令、CPU 时间及关键路径延迟分账。硬额内允许为时间保留容量，但不得无界缓存或让未来工作永久预付预算。

### 4.2 已选定的责任、接受与失败形态

**一个接受政策、两种真实目的地；输入按生存期表达。** 当前 selector 原位保留：普通是当前根，显式 history 是其 overlay/before。无需为统一“工作权威”增加长期 transaction、第三份树或独立 owner。真正 root 观察及普通操作返回后的 committed 可见性保持。

目标是删除 `proofValue→PublicationChange→新 Entry/Publication/authority 表→按 version 找回源/目标→通用费用解析` 的 native 重建链。根的实际实现仍为 `KisImageEpochReferenceModel.cpp`：保持 identity、revision、disjoint rebase、真实保护；紧接根构建就消失的 native epoch delta 可由原输入直接提供，长期事务的 immutable delta 保留其独立职责。

全体 metadata claims/单 shard 同窗、epoch 最后消费者及预算准入是不同事实；在原锁域各自裁决。可失败根/容量/费用/adapter 准备先完成，Published 安装仍由 epoch 原子接受回调统一耦合 metadata；Prepared 接受只更新真实显式事务的工作态。晚读者只补实际失效行的容量；root/default/注册变化沿原规则重准备，不重放像素或复制完整 D。成功后只交付；真实 provider/退款尾由原 record 接续。
