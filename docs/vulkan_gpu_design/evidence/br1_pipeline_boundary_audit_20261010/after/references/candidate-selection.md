# 候选记录与反例

在候选价值不明、需要比较多个解释或复盘预测偏差时使用。字段合入项目现有账本；按决策需要填写，不为每个代码片段另跑完整实验。

## 进入蓝图前保留什么

| 记录 | 判断用途 |
|---|---|
| 业务端点、同义分母、源码/库身份、观察覆盖 | 当前成本、基线额外成本、可回收净成本分别有何证据？未覆盖部分不能填零 |
| 必要事实/消费者/失效窗口、理想算法、当前放大公式 | 保留真实合同，确定可合法删除什么，而非从容易改的结构倒推方案 |
| 业务必要图与当前执行图、主要边界的依据、干预层级 | 热点的请求次数由谁产生？版本/发布/任务边界是否真有消费者；局部补丁是否固化可替代的上层拆分？ |
| 分支频率、大小/batch分布、数量和单价来源 | 原成本与替代成本是否处于可比上下文？调度相关数量与稳定事实分开 |
| 删除量、新增量、净CPU/wall范围、δ、已有噪声与可行精度 | 收益足以影响本目标吗？宽工程预算不冒充精确预测，CPU不直接换算wall |
| 竞争解释、反证、最小实验、停止条件 | 结果能否改变选择？关键净价未知时止于有界判别，不扩成产品大包 |
| caller持锁/回调/重入、原owner、失败与最终释放 | 检查是否把成本转移到其他路径，或引入新的死锁/寿命问题 |
| 准入理由、原索引/矩阵、独立确认及控制 | 区分主收益、实现依赖、顺带清理和必要保留，不重复领取共享预算 |

较大的责任桶只确定调查方向。合法净预算仍未知时，不必把所有责任完全定价才做下一实验，但不能声称已找到最大的可优化项。

## 当工作拆分本身是候选

对主要链记录`业务输入 → 必要观察/失败边界 → 实际job/operation → 页/版本/发布 → 最终释放`，给出关联身份和频率，而非只有互不相连的函数计数。单次函数已最简时，仍检查上游是否过度调用；融合有真实障碍时，标明是哪条语义边，而不是把“当前有独立API”当阻止重设计的充分理由。并非所有障碍都可消除，也不要求所有模式使用同一融合路径。

实验应区分：既定工作每次太贵、拆分造成工作过多、调度使合法并行工作等待。比较的最小完整责任覆盖受影响的准备、执行、交付和释放，不按逐容器优化累计收益。边界尚无合法替代时，先做消费者/可见点或依赖的有限判别，保留未知，不以全局最优证明为前置而停滞。

为每个不变量说明来源：业务输入、必须交付的结果/顺序/时效、诊断匹配条件或内部实现指标。原实验固定的任务数、更新通知数、版本数适合保持旧局部对照；它们不自动成为新结构实验的语义门。需要改变时另冻新协议并覆盖真实消费者、显示延迟、取消及资源边界；不改写旧样本或把少做用户需要的工作算收益。最终像素一致不能替代交互过程同义。

## 2026-10-09 至 10 的冻结反例

以下来自Krita BR1的空历史任务试行和后续排名审计，只解释本次规则修正，不是通用阈值，也不是当前项目状态。

- **次数与时间排序不同。** 高频Work释放引出了可删空任务，但后续同一配置的已观测独占分组中，history约0.637ms，前台准备/发布约4.043ms；history在该有限分组排第五。后台计时不覆盖全部准入、队列及跨阶段寿命，因此不能把0.637ms当候选严格上界，更不能当upstream额外成本排名。
- **删除次数不等于净删量。** 探索新节点734→212，确认机制样本868→212；B跳过760次请求，前后净节点差却是656。调度与任务合并改变了请求总数。数量与性能来自不同过程，不能直接相除得到节点单价。
- **过滤对非空路径有价格。** Undo/Redo各有56个非空新任务，增加查询却没有节点删除。Redo出现回退信号，但没有单独定价，不能把全部回退归因于getter。
- **caller清单还需持锁上下文。** 首版空历史检查从持shard锁的visitor回调重入getter，实际死锁。修订沿原锁内遍历保留旧准入；“都持owner锁”不足以证明能调用同一个快速路径。
- **宽预测命中不证明校准成功。** 工程范围0.2–1.0ms，探索参考0.66025ms，独立CPU节省0.4545ms，95%区间[−0.028,1.404]。点估计比探索低31.16%，并不证明真实收益下降31.16%；区间宽1.432ms，是原δ0.1ms的14.32倍，未确认达到原收益要求。

原生产候选已回退，边界测试保留。该批支持数量实施与否决流程实际运行，也暴露排名、净价和精度缺口；不支持宣称新的候选选择流程已准确命中前列瓶颈或完成正向收益闭环。一次已知反例回放也不能给出流程成功率。

这些规则可据反例纠错；选项价值与预测能力继续由事前冻结的新候选验证。无需为了准许更新技能而反复优化同一否决项。旧[引用归还示例](scoped-storage-example.md)保留其自身已测局部收益，不能替代新选择流程的独立验证。
