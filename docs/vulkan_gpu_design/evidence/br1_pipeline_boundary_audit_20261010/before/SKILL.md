# 算法成本驱动的性能优化

把“哪里慢”收敛为一个可证伪的问题：同一业务结果需要哪些工作，当前实现多做了什么，在保持合同的前提下能删多少，实测兑现多少。沿当前代码和项目有效合同工作；过去报告只证明各自冻结版本。

用户只要诊断时止于结论与可验证候选；授权解决时继续设计、实现和验证。复用项目已有证据、夹具和统计规则，不因应用本skill扩大项目范围、自动开启后台任务或要求例行批准。

## 先固定可比较的工作

- 明确一个操作的起止点、N/K等规模、有效输入/输出字节、历史/读者/缓存状态、实际完成量和清理终点。分别标注冷启动、steady、后台、drain；跨阶段寿命不能当作阶段内free。
- 固定当前源码、实际改动前版本、正式基线及各自运行库/依赖/构建参数。HEAD不能代表未提交源码；检查实际加载的库，不能只看编译成功或文件名。
- 先验证像素/结果、copy/COW/发布等工作量同义。逻辑写入字节、物理复制字节、分配请求、容量与驻留是不同分母。

## 建立三层成本账

| 层 | 必须回答 |
|---|---|
| 语义必要工作 | 在现有可见性、并发、预算、失败与寿命合同下，哪些字节、事实、决策和交接不可省？ |
| 可达到的理想实现 | 能否让同一事实只决定一次、同一寿命只保活一次、同一相关集合只访问一次？说明成立前提和必须保留的成本。 |
| 当前实现 | 沿实际consumer计数，分解重复准备/检查/复制/引用/查找/锁/结算，解释每个主要残差。 |

先列必要事实、真实消费者、变化/失效事件和最后使用者，再推导可执行的理想算法。现有代码做了某项检查，不证明该机制必要；当前fixture没有触发某种保证，也不证明公共合同允许删除。相对基线新增的合同须单列，其当前实现价格不能默认是必要成本。

用实际变量表达模型，例如`必要作用域 + 实际释放 + 必要交接E`或`变化域D + 全局约束G`。区分严格下界、可构造实现上界、工程目标和未验证猜测；两个规模点不能证明渐近复杂度。缓存或稀疏检查必须证明失效条件：未触碰状态也可能已超限，动态限额、跨类总额、负delta、溢出与并发不能被“通常不变”省略。

为一个候选预报可观察变化：`Δ请求/容量/检查/引用/锁/结算/字节`及保持不变的必要工作。未测单价时给数量模型和条件估算，不把计数占比当时间占比，也不把热点全部视作可删除空间。

## 用成本证据选择完整改动

1. 先读已有有效矩阵和源代码，列出竞争解释及能推翻它们的观测，再补能改变选择的最小诊断。调用栈热点要落到具体工作和责任，避免按一个容器或函数逐点猜改。
2. CPU、wall、等待与后台分开。exclusive机制账可相加；inclusive上下文相互重叠，不能相加。线程sample不自动等于CPU，外部进程/翻译层的时钟覆盖需验证。
3. 计数或重插桩用于机制验证；未插桩同义对照用于收益。短采样只定位，不伪装精确阶段时间或因果分摊；零样本不表示零成本。
4. 分开当前责任成本、相对基线额外成本、合法替代净可回收成本三种排名。调用/分配/free次数不是时间排名。声称榜首或前列，须给同分母的竞争责任和净预算依据；通过小改动的收益门只证明该项可能值得做。
5. 按有依据的可回收时间、业务端点、证据强度和完整迁移风险选一个有界责任。合法算法、实际命中、条件净预算与副作用验证方案齐备后，才进入产品优化蓝图；关键价格未知时，只领取有停止条件的判别实验或原型。

净预算扣除替代机制的新增成本与其他阶段、重试和最终释放的净增成本。新增过滤/准入检查须分别定价空工作、真实工作、已有任务复用和失败恢复；零删除路径仍会付检查成本。任务合并与排程可能改变请求总数，跳过次数不等于前后净删量。父责任桶时间不是全部可删预算；缺失单价填未知，不填零。

共同优化会同时改变比较双方的分母，重新计算剩余门槛缺口。不能靠旧比值差宣称增量收益。选择仍不明确时，按需读[候选记录与反例](references/candidate-selection.md)，复用项目原账本，不另建重复状态表。

## 深化设计并逐项迁移

实施前建立一张有限矩阵：`位置/真实consumer → 原owner、寿命与调用时持锁上下文 → 理想表达 → 删除或保留对象 → 保持的合同 → 行为/数量/时间证据 → 状态`。覆盖正常、拒绝、重试、取消、安装、移交和最终物理释放；模板/rebind、派生allocator、callback、worker、detach后的尾也属于consumer闭包。新增getter或检查须核验caller已持锁、锁内回调和重入条件；相同入口名不表示相同锁上下文。

优先调整原责任的粒度和表示，避免新增第二owner、账本、队列或恢复域。若引入缓存、类型或持久字段，比较直接表达，写明真实消费者、失效/寿命和净成本；不要为净删行数压缩语义。迁移所有受影响consumer，同批删除被替代路径；保留对象须有真实合同或调用者。

保存事前身份和预测后再动产品。实现调整导致删量缩小时，在确认实验前重算预算并保留旧预测；依赖项和顺带清理不虚领独立收益。按项目规则做可审阅补丁与聚焦提交。复用原测试，新增测试应能证伪实际合同；尤其覆盖优化假设失效的边界，不能只镜像新实现。

## 固定实验并核对预测

- 开始测量前确定端点、架构、配对顺序、样本量、排除/失败/停止规则和统计单位。沿用已有正式门；样本规模、bootstrap次数和阈值按项目及问题选定，不照搬示例。
- 根据业务价值、可回收差额及维护成本说明最小值得收益δ，同时用已有变异性评估可达到的精度。探索用于选择和定价，最终确认使用独立样本。实验若无法分辨目标效应，改用有据的新判别设计或保留未知，不追加样本到通过。
- 不与构建、另一基准或分析器竞争运行性能样本。记录命令、实际退出/timeout/reap、语义结果、源/库身份及全部原始失败。
- 先通过受影响安全与资源检查，再测机制数量，最后运行未插桩增量比较及原受保护控制。真实回归修复后开新批次；分析器错误可修后分析原样本，保留旧版本和理由，不借机换样。
- 配对/顺序块是独立单位，内部循环不能伪装独立样本。区分配对估计与边际中位数，报告区间方向与family范围。点估计超过阈值不等于置信下界通过，不加样到通过。
- 将事前预测、实测工作差、时间收益和残差放同表。分清工程范围、事前点预测、探索参考与统计区间；点估计落在宽范围内不证明预测准确，两个点估计之差也不证明真实效应变化。偏差分别检查模型、命中、实施、净增成本和测量精度，必要时回退候选；不能静默改变目标或靠同义微调延长本包。

## 有限收口

交付：已完成矩阵、实际删除/保留、生产/测试/派生物增删、源码与实验身份、原始数据及可复现分析、理论/实际对比、置信范围、未通过的正式门和下一优先责任。

分别裁决：机制是否兑现、局部增量收益是否成立、原控制是否回退、整个阶段是否完成。观测可重复性不等于概率置信区间，语义安全测试不等于统计性能资格。目标责任完成后停止扩样；下一痛点由更新后的剩余成本选择，不能重领已完成工作。

复盘技能时，可立即修正已由反例暴露的判断缺口；不要把规则修正、旧案例回放或准确否决等同于选项排名和收益预测已获正向验证。后者仍需新候选的事前选择、预测、完整实施和独立确认，不能为升级技能追逐一个正结果。

需要理解本线程的模型、反例与正确收口方式时，读[工作示例](references/scoped-storage-example.md)。其中数字属于冻结个案，不是其他项目的参数或当前状态。
