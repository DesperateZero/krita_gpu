## 4. 必须联合比较的设计，而不是独立累加收益

下表为证据覆盖/重叠表，不是新的实施状态矩阵。实施位置沿用原T项。

| 完整设计方向 | 对应原索引与现有责任旁证 | 原理、重叠和不能遗漏的成本 |
|---|---|---|
| 旧不可见工作目标及身份存储复用 | T03.1、T04.2/T04.3、T05、T07.2；cold/history/retirement | 把逻辑generation与物理寿命分开。只减少实际停止发生的建立/退出；与证明准入和回收优化重叠。必要写字节、每次接受、真实读者及失败回退保留 |
| 同一operation的准入、证明与布局合并 | T02、T03、T04；cold/seal/operation及其子项 | 未失效事实只产生一次；需列epoch、预算、provider/布局变化的失效事件。可能比减少物理对象更能覆盖广泛入口，当前缺联合净价，不能排除 |
| 固定cut的读、保护与最后归还 | T06.1/T07.2；显式read差额及write内读链 | 同一合法cut只选择和保活一次，连续读取保留native pin/驻留/last-use。不得把write比较与显式read合并成无限寿命cache；不能重领已删除的重复终结 |
| 发布粒度及中间投影统一 | T02.3/T02.4、T04.1–T04.7；H0 commit显著，H1较低 | 保持真实可见点、上一成功操作及拒绝隔离，只消除无consumer表示。fixture每写后立刻读取，不能把16次结果融合成一次；真实业务另查可见点。handoff仍受自身合同/M7约束 |
| 元数据退出、GC和队列批处理 | T04.8–T04.10、T07；history/retirement及诱发任务 | 必须比较“少生成待回收工作”和“保留工作但批量处理”。不能把整个后台桶领成调度损失，或将工作移到前台算删除；峰值/最后释放进度要付账 |
| 其他入口及共有业务 | T04.11/T04.12、T06.2/T06.3、T08 | clone/import/default/raw的N/D、别名和失败边界不同，按同义格报价。通用算法双侧交互另账，不能补PageStore的净预算空格 |

联合模型用实际消失的事件集合计一次：`总净收益 = 联合旧工作 − 联合替代工作`。如果身份复用已经消掉某次allocation/retire，不能再把这次操作中的metadata、预算锁、completion删除作为独立收益加入。若两方案不可区分，允许按更小状态/更少owner/更低风险选择并明确未证明榜首；不能靠任意合桶造出排名。

已测反证继续约束设计：立即前台回收命中960次却净回退；同步票据删1088次未通过CPU收益门。这否定各自实施/价值资格，不证明整个历史/退出都必要，也不允许把两个旧实验的点估计拿来给新组合减价。

## 5. 旧目标交接：已经关闭的问题与尚未运行的完整路径

**当前完整设计边界：** 旧目标保留只是[§19.15统一操作管线](../br1_pagestore_equivalent_pipeline_20261010/PIPELINE_PLAN.md#resident-operation-pipeline)的一部分，实施时与内部证明/布局事实归并、接受内旧Prepared退出、合格H0直接canonical及全部出口同时收敛。不能先交付一个cache再把此处条件少建量当整包收益。新[源码/条件事件索引](resident-operation-design.json)区分已测数量、路径推导和目标值；本页冻结成本及原图不新增任何测量。

[8过程交接探针](DONOR_LIFECYCLE_DESIGN.md)已纠正早期静态推导：`discardHistory`确实先准备RetirementDebt再删metadata，原`prepareBackingHandoff`确实只接Current/ActivePending；但metadata刚变Historical时，backing尚未转Debt。普通H1实测即时960次原组件准备/独占/取消成功，下一写896个已记录目标的metadata及owner均已退出。因此不放宽Debt入口，也不从已交退休队列的记录反向取回；缺的是提交退休前的跨操作保留。

当前条件设计已给出原持有者和收费类：原transaction/page槽附带最多一个备用handle，physical唯一owner及预付retirement record保持；作为ActivePending工作容量收费。仅保留不授写权，真正checkout才运行原physical claim。clone/native分别拒绝64/4次的反例说明该检查不能删。metadata接受内退出、备用移交及下次retag还没有实际实现，不能把明确设计写成运行正确。

```text
保留上一成功值、undo及真实reader
  → 原接受准备核验精确旧Prepared的逻辑保护
  → 接受时：旧逻辑退出，与原槽有收费备用责任一致移交
  → 下一写：新generation/descriptor准备 → 原独占claim → retag/rekey
  → 私有结果完成 → 原接受点 / adapter交付
  → 未命中、拒绝、取消、移除、commit/abort、close及晚释放沿原责任收尾
```

完整实现需要按[原33项内索引](DONOR_LIFECYCLE_DESIGN.md#4-原33项内的实现与删除索引)同时覆盖ProofMap全部consumer、metadata保护/退出、owner/binding换代及所有槽出口。上一成功值不能提前覆写，已接受不能假报失败；有保护则继续原路径。当前store额度在运营后冻结，待测固定/父共享额度压力；不声称动态改限已支持。实际provider revoke/swap、capture/pending read、alias、代次溢出和最后使用需要验证，不留到性能通过后补。

[源码行及SHA](donor-source-index.json)、[模型与数量](donor-model.json)和[真实能力计数](donor-summary.json)分别回答位置、条件构造、观测事实，三者不能互相替代。此处已经能定义完整替代的实验对象，仍不能给它填写净回收毫秒。

## 6. 可以确定的数量，与仍不能预测的收益

H1无持续外部保护、同布局全覆盖写、旧目标及时可用时，四寿命K页W次写的构造为：

```text
当前非默认物理建立 = 4K(W+1)
可构造的建立量     = 4K(1 + min(W,2))
K16/W16           = 1088 → 192，条件少896次
```

这是两个交替工作目标加一个undo origin的**条件构造**，不是已测理想下界，更不是只要做cache就必达。W1没有这种删量；H0没有相同Prepared证明，不套H1。generation和每次接受次数、17MiB公共写、18MiB显式读保持；内部字节初始化是否同时减少必须另证。

当前观测H1 payload峰值49已经接近该构造的每寿命48个非默认目标加1个默认对象，**少896次建立不代表峰值同比减少**。完整身份复用可能拉长保留时间、增加某预算类占用；保留空间必须使更多Fresh/拒绝/末尾回收的成本可计算。资源观察门未过，49不是原库峰值保证。

价格模型应写成：

```text
ΔI = 被真正消除的建立/退出/重复准入指令
     − retag与交接 − 资格检查（含未命中）− 保留/压力/重试/最后释放新增
ΔCPU 同样由完整两版配对实测；不以平均每指令CPU强行换算
```

仅为说明门槛，不是收益预测：本批current 183.129688M的15%为 **27.469453M**。如果净收益只来自少896个完整生命周期，平均每个必须净省 **30657.872条指令**；任何新增总代价还要先扣除。CPU 0.75ms门对应平均每个约 **0.837µs**的净门槛，统计确认仍要求完整case的95%下界，不是测单个对象即可通过。只达到15%工程门时，相对upstream仍余 **125.777509M** 指令差额，不能宣布整条PageStore已接近upstream或M6收敛。

不能使用 `99.7M × 896/1088` 作为预测或严格上界：不同桶包含不随物理次数减少的必要工作，history调用也不等于成功退休次数，并且观察条件不同。当前可回收指令/毫秒仍为null；“确切方案”允许诚实的预测区间，不要求也不可能保证一个精确毫秒点值。

## 7. 从此预算图到完整方案的有限路径

下一包按[§19.15完整方案及实施顺序](../br1_pagestore_equivalent_pipeline_20261010/PIPELINE_PLAN.md#resident-operation-pipeline)进入有界替代验证；该设计已覆盖下表合法路径对照和修改索引，实际安装、净价与控制仍待实现。以下是验收责任，**不再原样重采全量scope，也不先实施单个release/锁/节点微项**。

| 顺序 | 有限交付物 / 原位置 | 足以进入下一步的标准 |
|---|---|---|
| 先完成合法路径对照 | 原§19.4/§19.5内把身份复用与共同准入/批量退出的必要、删除、保留、新增事件逐一对照；关联read/发布的重叠。对§5五类设计问题给原owner/类/锁/转移点及失败路径 | 无悬空持有者、未收费保留、第二owner或接受后假回滚；不能实现的分支明确保留原路径。只对本包承诺的H1域定稿，不假装H0/所有入口已优 |
