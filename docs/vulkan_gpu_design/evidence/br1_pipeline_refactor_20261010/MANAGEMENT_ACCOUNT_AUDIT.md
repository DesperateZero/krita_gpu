# 管理成本账审计：总量已对上，单页预测模型尚未成立

2026-10-14；复核产品b7565f0f6f、现有原始机器账和候选选择。没有新增性能运行、产品改动或测试；不另建实施矩阵。当前执行入口92及原33×6矩阵继续有效。

**当前账本是有测量依据的分阶段/分函数支出表，尚不是能从理想算法推算单页指令数、并可靠排列可删成本的模型。** “总量加回去”“责任位置已知”“根因能解释这些指令”“替代后能省多少”是四个不同结果；前两项取得了限定范围证据，后两项仍明显不足。将最近几轮称作单页目标的有效主线推进，依据不够。

## 1. 产品、候选和账本分别处于什么状态

- 产品仍是b756；最近这些轮主要增加了诊断与派生候选。最新普通探索批H1产品write49.945405M、upstream6.032530M，产品额外仍为**43.912875M**。候选42.353654M剩余差额不是新产品基线。
- 同一分段组中，H1 write责任和50.271896M，加−0.331744M观察残差回到49.940152M，再减同批upstream6.027620M。这是位置/观测对账，没有推导出必要成本。
- `protocol-core-price-r0/accounting.json`的`necessary_instruction_price`和`ideal_implementation_net_price`至今都是`null`。未知不是零；没有证据把全部剩余费用称为正常管理，也没有证据把它们全部领取为可删。
- 4.28k暖非像素指令/页来自“希望回收75%差额，且暂时固定首两写与像素费用”的反推。它不是已构造出的理想协议价格，不能用它证明存在约90%的可删管理工作。

| 判断 | 实际证据状态 |
|---|---|
| 总量和大额位置 | 限定fixture内较充分，且保留有符号残差 |
| 全部管理动作及其状态条件、因果来源 | 部分建立；重复helper计数不等于完整动作普查 |
| 每类动作的实现单价、预算/引用/最后释放引出的费用 | 若干局部已定价；主要部分未按统一动作分解 |
| 同语义upstream的内部机制差额映射 | 端点对齐，内部账未统一；不能任意摊分upstream总价 |
| 必要金额、可达到的替代金额与可回收排名 | 未闭合；没有可承诺的整体单页价 |
| 最新合窗候选 | 普通探索写省1.559M，但一个小格读控制未过；未迁产品/未独立确认 |

## 2. 已经知道大钱在哪里，但尚未知道其中每笔为什么昂贵

以下只使用`pipeline-segment-r0`同一Backend组的896次后期页写，不与其他分组拼成新总账：

| 暖非像素责任 | 总量M | 按896页写均摊 |
|---|---:|---:|
| Target | 12.094957 | 13,498.836条/页 |
| Seal | 13.784848 | 15,384.875条/页 |
| 其他非像素工作，含范围/base/外层等 | 10.890063 | 12,154.088条/页 |
| 合计 | 36.769868 | 41,037.799条/页 |

这张表没有遗漏一个新的40M级总量黑洞。真正欠缺的是：这些大段里，身份定位、记录物化、通用容器操作、引用操作、父子预算手续和退出分别产生多少独占指令；各自是必要动作过多、相同动作实现太贵，还是测点边界仍含其他工作。

其他观察组已把physical plan、D、metadata准备/安装、proof、清理进一步分开，但它们来自不同观察条件和部分不同抽样状态，不能直接替换本表的父桶后宣称完整统一。特别是旧晚暖样本漏过第3/4写的收费过渡；修订ledger后价格从3.532M到3.965M。896个“物理复用页”包括128次收费过渡和768次零增量交接，**41k不是一个确定稳态的单价**。

“同一变化反复加工”仍是有源码支持的解释，尚未成为能复算数千万条指令的成本公式。它可能分布在许多常数开销中，不必有一个单函数独占大多数指令；分散也不等于必要。

## 3. 上轮为什么没有有效推进主目标

这是选项排序和实施范围失守，不能用小格控制异常解释：

1. 上轮前已经定价：暖metadata四准备段暴露约**1.895M**；即使全部免费，也只有约43.9M写差额的4.32%，且其中仍有必须保留的逻辑。
2. 原设计要求以稳定activity/result/D的完整事实链为判别单位；实际领取了合窗及同锁查询子集。事前净省预估0.6–1.4M，对主目标明显很小。
3. 又给该小包设0.5M“最低值得门”，相当于总差额约1.14%。通过它只说明小包值得局部实施，不能证明它是推进4.28k目标的前列方向。这个门没有落实用户的主线尺度。
4. 实际1.559M接近且略高于局部预测，说明局部价格并非完全估不准；问题是已知覆盖面很小仍被提升为主要下一步。安全测试数、净收益为正及控制是否通过，都不能补足选择依据。

因此保留该候选作为已知小额从属清理，不再用它证明主线方法有效。将下一步仅改成“更大的整体重构”同样不能修复缺失的成本模型；大改动也可能只改变表面结构。

## 4. 为什么现在还估不出主要成本点

- **现有测点主要按函数责任分组。** 例如一笔管理存储申请，会在当前caller中连带产生allocator、共享父预算准备/本地准备/结算、最后释放；按caller的费用虽能相加，却没有按产生原因去重归集。相同低层成本分散在Target、D、metadata和清理，无法直接回答“移除一种表示，整链减少什么”。
- **数量和价格没有形成可复算关系。** 21次activity查询/页只覆盖选中的helper，漏掉直接find；分配入口包含不同分支，free入口包含null早退。旧普查修复后仍增加33.51%写指令，不能把它当普通运行完整动作清单。新局部聚合只解决了metadata这一子集。
- **观察粒度限制尚未被解决。** 旧测量叶边界本身约1554条指令，可能大于被测的小动作；因此采取粗段/抽样。通过总量扰动门并不会自动恢复遗漏的调用条件或细粒度成本。不能不停把粗段命名得更细就当完成因果定价。
- **没有把C++表达落到主要机器工作。** 模板容器、RAII构造/析构、引用计数、值复制、状态初始化和原子/锁路径，可能把看似短的源代码展开成大量指令。此轮核对四个相关TU均为`-O2 -g -DNDEBUG`；未发现-O0这类简单解释，但没有完成编译产物层面的主要放大核对。
- **替代实现的费用长期留空。** 现有多数预测仍从旧桶挑一个比例，再由整包试验决定真假；没有先估清保留授权、引用稳定性、跨锁失效、取消与最终清理在新表示中的费用。这使“理想流程”实际上只是设计方向。

这些是当前方法尚未完成的工作，不是问题天然无法估计的证明。也不能因此反过来断言存在一个尚未发现的巨型单点。

## 5. 方法的下一有效产物必须是什么

下一产物应是**能复算现行页成本、再预测完整替代净价的机制账**，依附原矩阵；不以又一个正收益小补丁或新蓝图作为完成判据。

1. **定义确定状态和分母。** 分开首次建立、物理复用但收费过渡、收费稳定且metadata原槽复用、late-reader/重试；严格区分每cut固定费、每shard费、每页费、真实增长费、字节费和最后退出费。单页均摊不再掩盖固定成本。
2. **从最大的未解释责任向下追。** 先补Target/Seal的主要动作构成，不再由哪个helper易改决定方向。每笔金额只入一个独占主账；按“哪个状态变化生成了它”关联跨层消费者，不再重复计入父子桶。
3. **把次数与实现价格接起来。** 为每个有影响的动作记录真实分支/尺寸/次数、保留理由、当前指令价、从属预算/引用/回收工作。固定路径用源码与编译产物核验展开，动态次数用原循环局部聚合；只对足以改变选择的未知段补有限测量，不恢复高扰动逐函数时钟。先要求模型能预测当前操作及控制规模变化，误差独立列出，不靠拟合残差为零。
4. **给可执行的最小替代定价。** 同一真实owner、状态、并发和预算语义下，列出保留的原子步骤及旧动作删除量；对价格未知的新表示做最小可执行段的定价，不能用mock容器单价冒充真实管线。整体新价必须包含更早准备、失效重验、拒绝/取消、保留与最后释放。此阶段不先做整条大规模迁移。
5. **依据净预算选择完整干预。** 用已定价的动作差及替代单价解释预计净省；最大未解释费用不能大到足以改变候选排名或吞掉收益。候选必须说明能消掉单页差额的哪个显著部分；不足2M的已知清理可以附带，不能凭低δ自动晋升主线。4.28k只能作为要求检验的目标，是否可达要由可构造方案报价决定。
6. **原测试和独立普通对照用于反证模型。** 比较实测与事前预测的残差，归入命中错误、次数错误、单价错误、替代增费或观测误差；不以“有一点进步”判方法成功。控制失败独立保留，但不能遮住主线选错的问题。

这不要求先穷举所有平台/锁或证明数学意义上的全局最优。要求的是：在当前相对upstream多出数千万条指令的核心fixture上，主要费用有能加回当前成本的解释，下一方案有足以影响单页预算、能被实验否定的净价。现有skill已经要求分开责任/额外/可回收排名；本轮首先是未按这一要求选择完整干预，不能靠增加规则文字宣称技能升级完成。
