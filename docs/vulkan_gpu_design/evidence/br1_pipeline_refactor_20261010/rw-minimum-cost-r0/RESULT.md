# ed0f 读写差额：责任计价与最低成本路径

2026-10-12。产品仍为 `ed0f229821a0c9953cd07685a886010ee52e8f62`，没有产品改动。沿用[唯一33×6矩阵](../../br1_pagestore_equivalent_pipeline_20261010/PIPELINE_PLAN.md#whole-pipeline-change-index)。本报告回答统一协议后剩余成本在哪里、哪些工作是语义要求、哪些只是实现选择；不授予 M6 或优化净收益资格。

**结论：52.407M 差额可靠，之前对其必要性的归因不完整。** 本批独立普通库复现读写额外 **52.402M**，其中写 **49.057M**、读 **3.345M**。当前写端目标准备 **21.351M**、封印发布 **17.965M**，两者合占当前写指令 **71.37%**。原协议统一主要消除了表示分叉，并未消除反复建立、查询、接受同一页事实的工作。不能把剩余费用统称为正常管理成本，也不能把这两桶全部当作可回收预算。

本批把责任位置和数量推进到可检查层；**精确必要金额、完整替代净预算仍没有闭合**。尤其写入包络之外的 7.403M、目标准备内部余项 8.936M、封印余项 5.691M 仍需进一步区分真实准备、容器/分配、重复验证和退出；这些不是凭加法得到的“正常费用”。

## 4. 读端费用与锁分组的真实数量

| 互斥责任 | M，95%区间 |
|---|---|
| range capture | 1.991 [1.951,2.021] |
| resident read | 0.734 [0.734,0.734] |
| captured release | 0.475 [0.474,0.476] |
| read其余，含payload、backend及未包入的guard终结 | 6.133 [6.084,6.177] |
| 合计 | **9.333** |

前三项合计3.200M，与3.345M读差额处于相同量级；其余6.133M与upstream完整读5.988M只差约0.145M。这是**比较分解的数值关系**，不证明前三项可全部删除：upstream的同类定位/保护混在它的完整读端里，PageStore自身也必须保留exact保护与物理pin。

当前主格实测 retain、resolve、release 各1024次。按当前源码hash、surface=1、64 shards、4×4页范围计算，row-major shard序列为：

```text
2,3,0,1 / 35,34,33,32 / 0,1,2,3 / 33,32,35,34
```

只有8个不同shard，却有16个相邻段。当前按相邻同shard分组，不能兑现真正分组的减少。使用原range的一份ordinal→shard分组索引，可将retain/release各 **1024→512**，每页ref仍保留；若capture在原保护下同时交付exact binding，随后 **1024次slot重解析**才有条件消除。对应metadata锁入口模型从3072降至2048，进一步可至1024；这不是全部锁数量，更不是全部锁等待。分组索引、binding保活/失效及资源字节必须计入新成本。[可复算数量模型](minimum-model.json)，生成器绑定源码哈希。

## 5. 理论最低成本路径：严格下界与合法构造分开

主格是4个manager寿命，每寿命K16、连续16次写，每次写后立即完整读取并校验，history保留初值直到finish/undo/redo。输入每次真实改变。下界针对这些可观察行为，不能因为最终值相同而合并中间调用。

### 5.1 已能证明的最低责任

1. **64个真实可观察写入截面**和64个读结果，不能压成4次history commit。
2. 在现有页寻址合同下，必须表达1024个改变页结果、解析1024个读页；一般输入必须消费每方向16MiB有效字节。必要工作量是 `Ω(B + ΣK)`，不是“所有管理都可以O(1)”。常规布局每方向65536次256B行copy是当前算法推导数，**不是memcpy调用次数的严格下界**；双方都承担行布局转换，不能把共同字节成本当成PageStore税。
3. 旧history、真实retained reader、source、物理last-use及取消结果必须正确；独占、预算和原owner最终释放不能消失。必要的是这些事实成立，**不是为每次成立重新分配一份记录、跨两个owner反查一次、再重算一次**。
4. upstream本批12.016M/0.751ms是其能力子集的一种实现价格，不是PageStore完整合同的理论下界。没有证明一个带全部安全/资源保证的最低实现，不能从52.402M直接算“理论可省X毫秒”。

### 5.2 在新版协议内的最低工作路径候选

```mermaid
flowchart LR
  A[一次操作准入与原range] --> B[每页一次选择及私有结果]
  B --> C[真实物理许可与已有费用承接]
  C --> D[最终字节写入并完成原结果]
  D --> E[同一D准备必要安装存储]
  E --> F[动态事实复验并联合接受]
  F --> G[原overlay与exact范围保护]
  G --> H[同一owner取消或最终释放]
```

这条路径不新建owner、长寿命validated cache、第二份write set或替代协议。每一步的必要条件与当前差距如下：

| 必要事实 | 当前重复承载 | 更低成本表达 | 不能删的边界 |
|---|---|---|---|
| provider/layout、range及动态预算可用 | 1024页反复进入domain同步/预算入口；物理计划逐页独立准备 | operation建立短寿命计划；已有物理收费对象续用原责任，仅真实新增/类别变化作delta；原claim消费计划 | 1024次budget/domain是实测，**不等于1024次可删锁**；动态限额、父预算、公平等待、换域、取消debt与真实峰值保留 |
| 每页独占及原结果有效 | 1024 target/physical plan和reservePrivateWrite；Fresh分支重新建立其所需资源 | 原entry只携带一次选出的base、物理计划、slot与descriptor；后续直接消费这些受保护事实 | physical claim、revision、ABA、晚reader和真实Fresh不能被稳定缓存掩盖 |
| 新结果及旧overlay归属于本事务 | prepare和accept分别校验1024新proof＋960旧proof，共3968次查询；每次CPU查询进入ledger再进入shard | 新结果以原reservation/issuer的一次能力交付，旧结果在原overlay owner下证明；接受复验动态head，不重跑公共归属注册表 | **1984个新旧关系仍须成立**；只有保护期内不可撤销的typed事实才允许删外部反查；foreign/stale/generic校验保留 |
| D中的结果能无失败安装 | entry→changes排序→detachments→metadata输入，多轮扫描；准备后重复解读 | 原D作为唯一语义输入；只保留不同锁序/生命周期确需的紧凑安装计划、索引及缺失节点；动态容量在接受时复验 | 不能删candidate所保护的跨unlock快照、真实canonical root投影或晚reader补容量；控制格已观察到额外准备，触发机制未计 |
| 读者锁定自己请求的exact范围 | 每页retain后又按slot解析，再逐页release | 同一capture下取得所需exact事实，按真实shard分组，ordinal直接消费，原release节点终结 | 不保留范围外root来偷省K个ref；pin/epoch失效、压力、clone、swap与最后reader保持 |

**物理副本下界不能混用。** 可取消输出且before独立保留时，“before＋两份工作容量”是一种192个主页payload backing的构造模型（不含default及其他控制资源），不是全球最小性证明。before＋可原位覆盖current的128模型要求首字节前全预备且不可失败、没有旧current读者，并提供原子可见性；它属于更强M7条件。当前M7最多8页/256KiB fence，而主格K16，不能用该模型直接扣除当前费用或吞掉64个观察截面。本轮没有重测backing出生数，不把旧192/896数量模型冒充本批出生事件。

### 5.3 理论优化空间该如何定价

`净省 = 消失的原工作 − 新增的准备/索引/保护/失效/退出工作`。1024→64类计划入口、3968次查询、1024→512分组只是**条件删量**；它们没有统一单价，也不等价于同比例减少父桶。

- 下一完整方向是 **原operation计划→原私有结果→同一D接受**，同时覆盖21.351M目标和17.965M封印，以及它们之间重复传递事实的成本。39.316M是当前暴露，不能承诺回收39.316M，也不能再报价两个父桶相加的全部CPU。
- 只做proof查询，原执行量上限2.810M且必须扣替代；只做读分组，retain/release入口可各减半，但capture1.991M和release0.475M包含很多非锁工作，不能直接乘50%。
- 预算合批最多能将稳定operation维度准备从1024缩到64，而页级真实准入仍1024。若动态状态变化必须重准备，以实际失效数R计 `64+R`，不能把R假定永远为零。
- 本批未证明严格最低指令数/毫秒。候选可构造、可删数量与当前费用已分别列出；必须先把替代入口、失败终点、索引字节和冷补资源落实，再用普通同库测试领取净价。
