# 首次确认失败后的有界修正

原 `confirm/` 的固定8块48过程全部有效，不剔除慢样、不追加样本。主格写指令少5.100M，读却多0.384M（4.11%）；CPU收益、读非劣和11个CPU控制未过。保留原分析器、源码diff、运行库哈希、原始日志及 `read-copy-diagnosis/candidate-r0.dylib`。

普通 ARM 二进制反汇编证实：原复制行循环8条指令，新type-erased callback按引用捕获参数，循环约25条，反复读取可能被memcpy别名影响的capture。见 `read-copy-diagnosis/*-valid.s`。主格1024页×64行，条件增加约17×65536=1.114M循环控制指令；这是机器码数量模型，不是CPU定价，也不覆盖函数入口/退出。

修正只在既有同步回调入口将目标地址、源地址、行数、行跨度和字节数固定为局部值，再按固定跨度递增。真实copy量、exact cut、分片/窗口、物理pin、失败前缀和最后释放不变；不另加协议或快路径。先构建、核对新生成码、双架安全和机制计数，再开始 `confirm-2/`：沿用同一原基线和upstream、8块48过程、13格、统计单位、0.75ms及2%门，独立新样本；失败同样不补样。本次重测依据是真实源码纠错，不是上一轮区间未过。

预计行循环恢复8条，较首次候选删除约1.114M控制指令；净指令与CPU变化由新批次裁决，不要求点估计恰好等于条件模型。analyze.py仅增加可指定结果目录，统计算法不改；首次分析器保存在confirm/。
